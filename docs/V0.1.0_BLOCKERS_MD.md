## 2. 三个独立卡点

### 卡点 1：洞穴里无法获得剑

**用户报告**：玩家走到剑的位置，**剑没消失，玩家没变蓝**（"有剑"状态）

**复现路径**：
1. 启动游戏 v0.1.0
2. 玩家进入洞穴（走到户外顶部中央 CaveEntrance Area2D）
3. 走到 CaveEntrance 里的 SwordSpawn 位置（80, 130）
4. 剑应该消失，玩家 has_sword = true
5. **实际**：剑还在原位，玩家颜色不变

**代码**（`src/scripts/sword.gd`）：
```gdscript
extends Area2D

func _on_body_entered(body):
    if body.name == "Player" and body.has_method("pickup_sword"):
        body.pickup_sword()
        queue_free()  # ← 这里的 queue_free() 触发物理回调违规
```

**错误日志**（PowerShell 跑 exe）：
```
ERROR: Removing a CollisionObject node during a physics callback is not allowed
and will cause undesired behavior. Remove with call_deferred() instead.
  at: _notification (scene/2d/physics/collision_object_2d.cpp:99)
ERROR: Removing a CollisionObject node during a physics callback is not allowed...
  (连续 3 次重复)
```

**已尝试修复**：
- v0.1.0 改用 `body_entered`（之前用 `area_entered`，CharacterBody2D 不触发 area_entered）
- ❌ 但 `queue_free()` 仍在物理回调中调用

**@Cindy 建议**：
- `queue_free()` → `call_deferred("queue_free")`
- 或 `set_deferred("monitoring", false)` + 隐藏
- @general 尚未应用

**问外部 LLM**：
1. queue_free / call_deferred 哪个对？为什么？
2. 洞穴中没拿剑的根因是 queue_free 错误，还是 body_entered 检测本身失败？
3. 应该隐藏而不是删除吗？

### 卡点 2：菜单退出按钮无法选中

**用户报告**：M 键打开菜单，看到"装备：剑 ✗"和"退出"按钮——但**右半部分被裁切**，焦点（黄色 ^）在右上角但在退出按钮右半部分之外

**复现路径**：
1. 启动游戏
2. 按 M → 菜单弹出
3. 看到 "装备 / 剑无" + "退出" 按钮（但右半部分被裁掉）
4. 按左右键切焦点——焦点 ^ 出现但**无法有效选中退出**
5. 按空格 → 无反应或切焦点失败

**截图证据**（shot 2）：
- 菜单显示位置：x=80 到 x=240（mid）
- 文本"装备"显示完整
- "退出"按钮的右半边被裁掉
- 黄色 ^ 焦点出现在最右上（位置 ~x=350, y=140），**在退出按钮实际可见区域之外**

**代码**（`src/scripts/menu.gd`，基于 v0.0.5 commit `411619d`）：
- 菜单 layout 用了**绝对 position**而非 viewport-relative
- quit 按钮 position 在 viewport 外（如 x=400+），但 input 监听在 viewport 范围内

**`project.godot` 关键配置**：
```ini
[display]
window/size/viewport_width=240
window/size/viewport_height=160
window/stretch/mode="viewport"
window/stretch/aspect="keep"
```

**已尝试修复**：
- v0.0.9 改 `stretch_mode = disabled`（用户报告：1x 完整但 2x/3x 仍裁切）
- v0.1.0 改 `stretch_mode = viewport` + `aspect = keep`
- ❌ 仍裁切

**@Cindy 推测根因**：
- UI 元素位置用 `OS.window_size` 而非 `get_viewport_rect().size`
- 菜单 layout 用了 anchor_center + 绝对 size，但 size 没根据 viewport 缩放
- 修复方向：`set_anchors_and_offsets_preset(PRESET_CENTER)` + `size = content_minimum_size`

**问外部 LLM**：
1. Godot 4.7.2 stretch_mode=viewport + aspect=keep 在 Window 大于 viewport 时如何居中？
2. Control 节点 position 应该用什么坐标系？viewport 还是 OS window？
3. 怎么用 anchor + offset 让 Control 永远在 viewport 中央？

## 4. 关键工程经验（R02 V0.4 已沉淀）

R02 §6.4.3 写入的实现硬约束（v0.0.6 之后被 v0.0.5 E02.5 违反过）：

1. **玩家视觉**：必须用 `player.gd` 的 `_draw()` 画矩形（不依赖 .tscn 序列化）
2. **场景装饰视觉**：CanvasItem 下不要挂 ColorRect；若需装饰，用 `Polygon2D` 或 sprite
3. **菜单/UI 文字**：Label + 显式 `theme_override_fonts/font` 指定像素字体（如 Press Start 2P）
4. **位置**：StaticBody2D / CharacterBody2D 不要手动写 `position` 在 `.tscn` 里

**疑似遗漏的约束**：
- **菜单/Control 位置**：必须基于 `get_viewport_rect().size` 而非 `OS.window_size` 或绝对像素
