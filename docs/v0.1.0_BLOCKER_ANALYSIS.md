## BUG-1：洞穴剑无法拾取

### 复现步骤

1. 启动游戏（Surface Pro 8，Win11）
2. 主角走到地图顶部，**进入洞穴**（cave 场景）
3. 走近灰色剑（接触后理论上应触发拾取）
4. **期望**：玩家变蓝、剑消失、菜单显示「装备：剑 ✓」
5. **实际**：玩家颜色不变，剑仍在原位；菜单显示「装备：剑 无」

### 相关代码（commit `4d6ef17`）

**`src/scripts/sword.gd`**（Area2D，监听身体进入）：

```gdscript
extends Area2D

signal sword_picked_up

func _ready() -> void:
    # 同时监听 area 和 body 进入（player 是 CharacterBody2D）
    body_entered.connect(_on_body_entered)

func _on_body_entered(body: Node2D) -> void:
    if body.name == "Player":
        body.pickup_sword()
        queue_free()  # ⚠️ 这里在 physics callback 中直接 queue_free，触发 ERR-1
```

**`src/scripts/player.gd`**（CharacterBody2D）：

```gdscript
func pickup_sword() -> void:
    has_sword = true
    queue_redraw()
    # 通知 game manager
    if get_tree().get_nodes_in_group("game").size() > 0:
        get_tree().get_nodes_in_group("game")[0].on_player_get_sword()
```

**`src/scripts/game.gd`**：

```gdscript
func on_player_get_sword() -> void:
    has_sword = true
    save_game()
    if player:
        var cr = player.get_node_or_null("ColorRect")  # ⚠️ 引用旧 ColorRect 节点
        if cr:
            cr.color = Color(0.5, 0.8, 1.0, 1.0)
```

### 关键问题点（外部 AI 分析时请关注）

1. **sword.gd 用的是 Area2D，Player 是 CharacterBody2D**（@Cindy 补充确认）：
   - Area2D 的信号是 `area_entered` / `body_entered`，两者都能用
   - v0.0.9 之前用的是 `area_entered`，v0.0.9 改成 `body_entered`——这个方向变更可疑
   - Player（CharacterBody2D）默认 collision_layer=1，Sword（Area2D）默认 collision_mask=1 → `body_entered` 应当能触发
   - 但触发后 `body.name == "Player"` 的判断**不一定成立**（节点名依赖实例化时的 name 字段）

2. **`cave.tscn` 中 Sword 节点的 collision_layer / collision_mask 配置**是否正确？

3. **`on_player_get_sword` 里引用 `player.get_node_or_null("ColorRect")` 是历史遗留**（旧版用 ColorRect 渲染玩家），新版本玩家用 `_draw()` 渲染，**没有 ColorRect 子节点**——这一行 `if cr: cr.color = ...` 永远不会执行。**这不是 BUG-1 的根因，但是潜在的隐藏 bug**。

4. **是否在 `cave.tscn` 中真正实例化了 Sword 节点？**还是只用了 `SwordSpawn` 占位？

5. **`body.name == "Player"` 判断是否可靠？** 建议改为 `body.is_in_group("player")` 或 `body.has_method("pickup_sword")`

### 已尝试的修复（v0.1.0）

- ✅ 把检测从 `area_entered` 改为 `body_entered`（`sword.gd` line 5）
- ❌ 仍未解决问题——剑仍然不可拾取

## BUG-2：菜单「退出」按钮无法选中

### 复现步骤

1. 游戏中按 `M` 键打开菜单
2. 按 `←/→` 切换「装备」和「退出」焦点
3. **期望**：当前焦点项显示黄色 `^` 箭头 + 空格触发（退出项触发确认弹窗）
4. **实际**：按 `→` 时焦点箭头出现在「装备」项旁边，但「退出」按钮**从未被选中**；按空格无响应

### 截图证据

shot2 显示菜单展开后，**两个 `^` 箭头同时可见**（或者位置错位），「退出」按钮右侧被裁剪。

### 相关代码（commit `4d6ef17`）

**`src/scripts/menu.gd`**（核心输入处理）：

```gdscript
func _input(event: InputEvent) -> void:
    if not visible:
        if event is InputEventKey and event.pressed and event.keycode == KEY_M:
            _open()
        return
    if not (event is InputEventKey and event.pressed):
        return
    match state:
        State.MENU:
            if event.keycode in [KEY_LEFT, KEY_A]:
                selected = 0
                _update()
            elif event.keycode in [KEY_RIGHT, KEY_D]:
                selected = 1
                _update()
            elif event.keycode in [KEY_M, KEY_ESCAPE]:
                _close()
            elif event.keycode in [KEY_SPACE, KEY_ENTER]:
                if selected == 1:    # ← 只有 selected==1 才退出
                    _show_confirm()
```

**`_update()` 函数**：

```gdscript
func _update() -> void:
    arrow1.visible = (selected == 0)
    arrow2.visible = (selected == 1)
    # ...
```

### 关键问题点

1. **`_open()` 初始化时** `selected = 1`（退出项），但 `_update()` 在 `_open()` 末尾调用，但 `arrow1.visible = false`、`arrow2.visible = true`——所以应该看到**退出项的箭头**。但截图显示两者都看不见，或位置错位。

2. **菜单 UI 布局问题**：
   - 主面板 `offset_left = -72`、`offset_right = 72`（宽 144），但内容用了 `HBoxContainer` 加 `VBoxContainer` 三层嵌套。
   - 「装备」+「退出」两栏：装备有 `arrow1 + "装备" + "剑:有/无"`，退出有 `arrow2 + "退出" + "→ ← 选"`
   - 加上 `HBoxContainer.add_theme_constant_override("separation", 28)`，**整个菜单宽度可能超过 144 px**，导致右侧被裁剪。

3. **viewport 是 240×160**：
   - 菜单宽度 144 + 居中 → 左 48、右 48，刚好。但加上 separation 和内容可能超。
   - 240 像素宽 + 144 菜单 + 边距 = 应该在范围内。**但用户看到的是「退出」按钮被裁剪**，说明实际渲染宽度 > viewport 宽度。

4. **`_input()` 是否被 `sword.gd` 等节点的输入处理抢断？**
   - sword 已 queue_free 后不应继续拦截
   - 但 cave 场景中可能有其他 Area2D 还在 `monitoring`

5. **画面缩放问题**：
   - `project.godot` 中 `stretch_mode` 和 `aspect` 设置影响 input 坐标到 viewport 坐标的映射
   - 如果 stretch 模式把鼠标/键盘坐标搞错，按键事件可能落到错误区域

### 已尝试的修复（v0.1.0）

- ✅ 把 input handler 从 `_unhandled_input` 改回 `_input`（`menu.gd` line ~135）
- ❌ 仍未解决——菜单「退出」按钮仍无法选中

## ERR-1：拾剑触发引擎错误

### 错误原文（shot3）

```
ERROR: Removing a CollisionObject node during a physics callback is not allowed and will cause undesired behavior. Remove with call_deferred() instead.
    at: _notification (scene/2d/physics/collision_object_2d.cpp:99)
```

连续 3 次（用户试了 3 次拾取）。

### 已知根因

**`sword.gd` 第 12 行**：

```gdscript
func _on_body_entered(body: Node2D) -> void:
    if body.name == "Player":
        body.pickup_sword()
        queue_free()  # ← 直接在 physics callback 中删除 CollisionObject
```

`body_entered` 是 Godot 4 的物理回调（由 `_physics_process` 触发），**不允许在回调内同步删除 CollisionObject**（包括 Area2D）。

### 正确修复

按 Godot 4 文档，应该用：

```gdscript
func _on_body_entered(body: Node2D) -> void:
    if body.name == "Player":
        body.pickup_sword()
        call_deferred("queue_free")  # ← 延迟到下一帧再删除
```

或设置 monitoring 为 false：

```gdscript
func _on_body_entered(body: Node2D) -> void:
    if body.name == "Player":
        body.pickup_sword()
        set_deferred("monitoring", false)  # 关闭监听避免重复触发
        queue_free()  # queue_free 本身是延迟的，可以保留
```

> 错误日志里的"`call_deferred()` instead"明确指明了修复方式。

### v0.1.0 状态

错误日志仍然出现——说明**剑仍在被检测到**（body_entered 触发）但 `queue_free()` 引发错误。这与 BUG-1（剑不可拾取）矛盾——如果 body_entered 没触发，不应该有 3 次错误。

可能的解释：
- **body_entered 触发了**，但 `body.name == "Player"` 判断**永远 false**（name 不匹配？）
- → 导致 `pickup_sword()` 没调用、`queue_free()` 没调用
- → 但 power shell 错误仍然出现，说明 `queue_free()` 还是被调用了？

**这是矛盾现象，需要查 `sword.gd` 的实际执行路径**。
